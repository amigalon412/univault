===================================================
These NEXT_PUBLIC_* values are already compiled into app/ — nothing to set on
the server. To CHANGE any of them you must rebuild (see DEPLOY.md "Rebuilding").

Set on the SERVER, not baked in (see DEPLOY.md)
================================================
ADMIN_PASSWORD    required to enable /admin; without it the page is switched off
BLUR_DATA_DIR     where /admin stores the published $BLUR address
                  (the unit sets /var/lib/blurvault)

NEXT_PUBLIC_BLUR_TOKEN is intentionally NOT baked in. The $BLUR contract address
does not exist until launch and is published from /admin at runtime instead, so
putting it on the site never requires a rebuild.

What is new since the last bundle
---------------------------------
* A slow green meteor shower behind every page, falling top-right to
  bottom-left. One canvas, one animation frame loop, no scroll listener; it
  stops itself in a background tab and does nothing at all under
  prefers-reduced-motion.
* Homepage vault card: switching STEADY/BALANCED/GROWTH now replays the
  allocation meter instead of snapping, at half the old speed; the figures
  churn and settle rather than swapping; the four basket weights drift off
  target and are pulled back on a nine-second loop, which is the rebalancing
  the card describes.
* The three pixel marks in the trust section draw themselves in from the
  centre outwards over a second.
* Every contract address in a docs table is now a link to Blockscout. The
  contracts page listed all twelve as plain text before, with no way to reach
  the explorer from the one page whose job is listing them. Addresses are
  rendered in checksummed form throughout.
* Docs no longer state anywhere that $BLUR has not launched. That claim now
  lives in exactly one place, the site header, which flips by itself the
  moment an address is published from /admin.
* AnimationGovernor, which pauses endless animations off-screen, only scanned
  the page during its first four seconds. Anything remounted later -- the
  vault card does exactly that on every strategy click -- was never governed
  and ran for the rest of the session. It now picks up animations as they
  start.

All twelve deployed contracts are source-verified on Blockscout as of this
build, and every address the site renders was checked against
contracts/DEPLOYMENTS.md: no superseded or abandoned address appears anywhere,
and every link points at the address printed next to it.

Smoke-tested from this folder before packing, not from the repo build: all
pages serve, /admin rejects a wrong password and a malformed address, and
publishing an address flips the header and all five docs pages that mention
it, survives a restart, and clearing it puts everything back.
