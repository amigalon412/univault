Set on the SERVER, not baked in (see DEPLOY.md)
================================================
ADMIN_PASSWORD    required to enable /admin; without it the page is switched off
BLUR_DATA_DIR     where /admin stores the published $BLUR address
                  (the unit sets /var/lib/blurvault)

NEXT_PUBLIC_BLUR_TOKEN is intentionally NOT baked in. The $BLUR contract address
does not exist until launch and is published from /admin at runtime instead, so
putting it on the site never requires a rebuild.

What is new since the last bundle
---------------------------------
* Sections now arrive as you scroll to them: a block fades up out of a slight
  blur over a second, with the supporting cards following a beat behind the
  prose. Previously only three blocks on the page did this and everything added
  since simply appeared.
* The vault card drifts a few pixels vertically on a nine-second cycle -- the
  same period as the drift/rebalance loop inside it, so the panel breathes in
  time with the basket it is showing.
* The primary call to action carries a slow halo, which stops on hover so the
  button's own hover state still reads as a response.
* Removed a dead .reveal rule that had been in the stylesheet unused. It
  carried an animation whose fill outranks normal declarations, so it silently
  fought the new reveal and which one won depended on whether an unrelated
  animation had finished.

Two things were deliberately NOT copied from the reference site this motion
came from. Its cards tilt as they float; at this panel's width that drags one
end of a horizontal rule nearly 6px below the other, and the whole instrument
is drawn in 1px rules, so it read as hung crooked rather than floating. And its
blur runs on the same one-second clock as the fade; filter is not composited
while opacity and transform are, so under load the block finishes fading in
before it sharpens. The blur here lands at 550ms so it always finishes first.

The reveal's hidden state is gated on `@media (scripting: enabled)`. With
JavaScript off the rule does not apply at all and the page renders normally,
unanimated -- the content is server-rendered either way. An engine that does
not recognise the feature also fails open.

All twelve deployed contracts remain source-verified on Blockscout, and every
address the site renders was checked against contracts/DEPLOYMENTS.md.

Smoke-tested from this folder before packing, not from the repo build: the
homepage, /app and all 25 docs pages serve 200, the contracts page still
carries its 12 explorer links, /admin rejects a wrong password (401) and a
malformed address (400), and publishing an address writes it checksummed,
flips the header, and clears back to null.
